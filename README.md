# PulseUp для Android

Это устанавливаемая Android-оболочка (WebView), которая открывает опубликованный сайт https://pulseup0.github.io/PulseUp/. Чаты и аккаунты продолжают работать через уже настроенный Supabase. Требуется интернет.

## 1. Создать Android-репозиторий и получить пробную сборку

1. Создайте новый публичный репозиторий GitHub с именем `PulseUp-Android` под аккаунтом `pulseup0`. URL репозитория должен быть `https://github.com/pulseup0/PulseUp-Android`, потому что карточка загрузки на сайте использует ссылку на релиз этого репозитория.
2. Распакуйте архив и загрузите **содержимое** папки `PulseUp-Android` в корень репозитория. Обязательно загрузите скрытую папку `.github` с workflow.
3. Сделайте Commit changes в ветку `main`.
4. Откройте **Actions → Build PulseUp APK**, дождитесь успешного завершения и скачайте артефакт `PulseUp-Android-APK`. Внутри будет `app-debug.apk`, пригодный для первичной установки и тестирования.

## 2. Опубликовать APK, чтобы его могли скачать участники PulseUp

1. В Android-репозитории откройте **Releases → Draft a new release**.
2. Создайте тег `v1.0.0` и опубликуйте релиз. Создание тега запустит workflow.
3. В **Actions** откройте запуск для тега `v1.0.0` и дождитесь завершения. Workflow прикрепит к релизу файл `PulseUp.apk`. Если в форме релиза сначала был создан пустой релиз, workflow обновит его и добавит APK.
4. Проверьте ссылку `https://github.com/pulseup0/PulseUp-Android/releases/latest/download/PulseUp.apk`. Она станет доступна после публикации файла в релизе.

## 3. Показать карточку скачивания на сайте

В комплекте отдельно подготовлен обновлённый `index.html` с карточкой «PulseUp для Android». Загрузите его в корень основного репозитория `pulseup0/PulseUp` **после публикации APK**. Карточка показывается авторизованным участникам на экране сообщений, скрывается по кнопке × и не показывается внутри самого Android-приложения. До появления релиза кнопка скачивания не будет работать.

## Что поддерживает оболочка

- JavaScript, Web Storage и cookies, необходимые для входа в Supabase.
- Выбор файлов/фото/видео через системный picker.
- Запрос разрешений камеры и микрофона для сайта.
- Кнопку «Назад» для перехода внутри сайта.
- Внешние ссылки открываются в браузере.

## Важно для бета-версии

- Этот workflow создаёт **debug-подписанный бета-APK** для тестирования вне Google Play, а не production-релиз.
- APK должен быть собран в GitHub Actions; этот рабочий контейнер не содержит Android SDK, поэтому готовый APK здесь не был скомпилирован или проверен на устройстве.
- Перед распространением постоянных обновлений желательно настроить собственный закрытый ключ подписи Android Release через GitHub Secrets. Иначе более поздние debug-сборки могут не устанавливаться поверх предыдущей из-за отличающейся подписи; понадобится удалить старую beta-версию и установить новую. Удаление приложения может очистить локальный вход, но чаты остаются в Supabase.
- Нативные push-уведомления Android пока не реализованы.
